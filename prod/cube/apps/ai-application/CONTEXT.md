# AI 应用 · 助手对话

用户在智能体对话中输入问题，并可附加知识库、技能等上下文资源后发送。

## Language

**引用（Reference）**：
对话输入区可附加的上下文资源；当前包括知识库与技能两种类型。
_Avoid_: kb、知识库菜单、skill menu（作为弹层/状态命名）

**引用选择器（Reference Picker）**：
用于浏览、搜索并勾选引用的浮层 UI；由「知识库」「技能」按钮，或输入 `@` / `/` 触发。
_Avoid_: 知识库弹层、kb popover

**引用菜单类型（Reference Menu Type）**：
引用选择器当前展示的资源子集，仅两种：`kb`（仅知识库）、`skill`（仅技能）。弹层关闭时不存在第三种「混合」模式。

**引用触发符（Reference Trigger）**：
在输入框内唤起引用选择器的快捷键：`@` 仅筛选知识库，`/` 仅筛选技能。输入框 placeholder 应明确写出两种触发方式。

### 思考过程展示（Thinking Process Display）

助手在给出正文答案前，对「中间过程」的展示形态；默认走**思考步骤**。另有 `prose` / `feed` / `descriptive` / `compact` / `silent` 逃生档。

> **前提（alpha.16 真流式）**：正文气泡不再是「done 才整段出现」的假流式，而是逐字 live 流出 + 事后 `message-reset-v1` 回溯清空（见 SDK `AssistantStore.resetInProgressAssistantContent`，迁移指南 / 上游 ADR-0035）。**思考步骤**正是为此设计——叙述归步骤区、气泡只流最终答案。

**思考步骤（Thinking Steps · 方案 B）**：
默认形态（`steps`）。把一轮拍平成**线性步骤时间线**：每个「步骤 N」= 一段模型叙述 + 它触发的**内联工具卡**（图标 + 名称 + 完成/失败）+ **耗时**；**不成树、不嵌套**。叙述留在步骤区，**正文气泡只流最终答案**。结束折叠为「思考过程 · N 步 · M 次工具 · 已思考 Xs」，可点开回看。
_Avoid_: 叫它 detailed / 思考树（那是可展开嵌套树）；把叙述塞进正文气泡

**思考文本（Thinking Prose）**：
可选形态（`prose`）。把一轮所有阶段拍平成**一段连续叙述**流进同一容器、打字机匀速吐字。⚠️ alpha.16 后正文气泡也会真流式中间叙述，多工具轮下 prose 面板与气泡会短暂**双重叙述**（可接受的可选档小瑕疵）。
_Avoid_: 叫它 detailed / 树 / reasoning 面板

**思考流（Thinking Feed）**：
可选形态（`feed`）。把过程拍平成**追加式状态行**，每行一个活动 + 计时；高度封顶、结束折叠。同样有多工具轮双重叙述小瑕疵。
_Avoid_: 与「思考步骤/思考文本」混用；activity list

**单行摘要（One-liner Summary）**：
可选形态（`descriptive`）。**单行覆盖** + 流式摘要短语，不可展开。

**思考树（Reasoning Tree · detailed）**：
可选形态（`detailed`，调试用）。**树状分支**，lifecycle → tool-loop → tool-call 每个 step 独立可展开，含 token / 参数 / 输出；数据层沿用 SDK `reasoning` 术语。
_Avoid_: 把它当默认；与「思考步骤」混为一谈（steps 是扁平时间线、不可逐节点展开）；面板标题写「推理」

## Relationships

- 一次对话可附加零个或多个**引用**；已选引用列表属于输入区 draft，与弹层开/关状态独立
- **引用选择器**按**引用菜单类型**过滤可选项
- 输入 `@` 时，**引用菜单类型**为 `kb`，搜索词与 `@` 后文本同步
- 输入 `/` 时，**引用菜单类型**为 `skill`，搜索词与 `/` 后文本同步
- 从**引用触发符**菜单选中引用后，`@query` / `/query` 从输入框移除，引用进 chips；选中逻辑本阶段留父组件，后续再内聚

## Example dialogue

> **Dev:** 用户输入 `@应急`，弹层里出现技能列表——对吗？
> **Domain expert:** 不对。`@` 只应出现**知识库**；技能要用 `/` 触发，**引用菜单类型**为 skill。

## Flagged ambiguities

- 历史代码用 `kbMenu*` 命名弹层状态——已决议：统一改为 **Reference** 命名体系，与 UI「知识库/技能/@ 引用」并存但不混用为状态名。
- **代码与领域不一致**——已决议：重构时实现 `@`→知识库、`/`→技能；移除键盘触发的混合列表（`all`）模式。
- **「思考」vs「推理」命名**——已决议：**UI 统一用「思考」**（对齐现有 `COPY_REASONING_PANEL_*` 文案），弃用截图/SDK 的「推理」作面板标题；`reasoning` 仅保留为 SDK/数据层内部词。折叠标题用「已思考 X 秒」。
